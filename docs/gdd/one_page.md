# 〈游戏名〉一页策划

## 玩法

**循环：** 〈动词〉 → 〈动词〉 → 〈动词〉 → 再来。〈这个循环为什么有意思，一句话〉

| 玩家能做 | 世界会做 |
| --- | --- |
| **〈动作〉**：〈效果，关键数字〉 | **〈对象〉**：〈它怎样变化或行动〉 |
| **〈动作〉**：〈效果，关键数字〉 | **〈对象〉**：〈它怎样变化或行动〉 |

**赢：** 〈条件〉\
**输：** 〈条件〉；〈输了之后怎样重来〉

## 体验

1. **〈支柱一〉**：〈两个方案冲突时，选哪个〉
2. **〈支柱二〉**：〈……〉
3. **〈支柱三〉**：〈……〉

## 设定

- **操作**：〈动作和按键，键盘 / 手柄〉
- **镜头**：〈2D 或 3D，跟随谁，能不能转〉
- **时间**：〈实时或回合制；暂停时什么停；有没有慢动作〉
- **画面与声音**：〈各一句〉

## 范围

- **必须有**：〈没有它游戏就不成立的东西〉
- **时间够再做**：〈……〉
- **这次不做**：〈……〉
- **做完的标准**：〈怎样算这一版做完了，两三条〉

## 细则与待定

开工时，一页写不清的核心规则写成玩法系统策划案；M1 之后，每块要开发的内容都先写一篇细则文档。细则按类型放在 `systems/`、`ui/`、`levels/`、`content/`、`art/`，选哪个模板见 [写法说明](../templates/gdd_guide.md) 的“一、文档组成”。

- 〈核心机制〉：gameplay，M1 前，待写
- **待定**：〈问题〉（〈谁来定〉，〈最晚什么时候〉，〈阻塞或不阻塞〉）
